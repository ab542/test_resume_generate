## 一、minium 自动化实战

### 1.1 minium 是什么

微信官方出品的小程序自动化框架，Python 编写。底层通过 WebSocket 连接微信开发者工具，调用远程调试接口来操控小程序。

```
┌──────────┐  WebSocket   ┌────────────────┐
│ minium   │ ────────────→ │ 微信开发者工具    │
│ (Python) │ ←──────────── │ (远程调试服务)    │
└──────────┘              └───────┬──────────┘
                                  │ 操控
                          ┌───────▼──────────┐
                          │   小程序真机/模拟器  │
                          └──────────────────┘
```

### 1.2 安装与环境

```bash
pip install minium
```

微信开发者工具 → 设置 → 安全设置 → 开启「服务端口」（默认 9420）。

# test/conftest.py
import minium


class BaseTest(minium.MiniTest):
    """所有测试用例的基类，封装通用操作"""

    def setUp(self):
        super().setUp()
        # 每个用例开始前清一下 Storage，保证用例独立
        self.app.call_wx_method('clearStorageSync')

    def login(self, email='test@example.com', password='123456'):
        """封装登录流程，供其他用例调用"""
        self.app.navigate_to('/pages/login/login')
        page = self.app.get_current_page()
        page.wait_for(5)

        # 输入账号密码
        page.get_element('input[name="email"]').input(email)
        page.get_element('input[name="password"]').input(password)
        page.get_element('.login-btn').tap()

        # 等待跳转
        page.wait_for(3)
        return page


# test/test_login.py
class TestLogin(BaseTest):

    def test_login_success(self):
        """正常登录"""
        self.app.navigate_to('/pages/login/login')
        page = self.app.get_current_page()

        page.get_element('input[name="email"]').input('liying@ama-auto.com')
        page.get_element('input[name="password"]').input('3149390154Li')
        page.get_element('.login-btn').tap()

        # 等登录结果
        page.wait_for(5)

        # 方式1：检查页面跳转
        current_url = page.path
        self.assertNotIn('login', current_url, '登录成功应跳离登录页')

        # 方式2：检查 toast 提示
        page.wait_for(2)
        toast = page.get_element('t-toast')  # TDesign toast
        if toast:
            self.assertIn('成功', toast.inner_text)

        # 方式3：检查 token 写入 Storage
        token = page.evaluate('wx.getStorageSync("star-token")')
        self.assertTrue(token, '登录成功应写入 token')

    def test_login_empty_email(self):
        """邮箱为空——应提示"""
        self.app.navigate_to('/pages/login/login')
        page = self.app.get_current_page()

        page.get_element('.login-btn').tap()

        # 检查错误提示

    def test_login_wrong_password(self):
        """密码错误"""
        self.app.navigate_to('/pages/login/login')
        page = self.app.get_current_page()

        page.get_element('input[name="email"]').input('liying@ama-auto.com')
        page.get_element('input[name="password"]').input('wrong_password_123')

        # 仍在登录页

        # 或检查 toast
        toast = page.get_element('t-toast')
        if toast:
            self.assertIn('失败', toast.inner_text)

    def test_login_network_error(self):
        """网络异常时的表现"""
        # mock wx.request 返回超时
        self.app.mock_wx_method('request', result={
            'errMsg': 'request:fail timeout'

        page = self.app.get_current_page()

        # 应该有网络异常提示

class TestNavigation(BaseTest):

        for i in range(9):
            self.app.navigate_to('/pages/search/index')
            page = self.app.get_current_page()
            page.wait_for(2)

        pages_before = page.evaluate('getCurrentPages().length')
        self.assertEqual(pages_before, 9, '目前应 9 层页面')

        # 第 10 次跳转
        self.app.navigate_to('/pages/search/index')
        page = self.app.get_current_page()
        page.wait_for(2)

        pages_after = page.evaluate('getCurrentPages().length')
        self.assertEqual(pages_after, 10, '最多 10 层页面')

    def test_switch_tab_clears_stack(self):
        """switchTab 会清空页面栈"""
        # 先跳几层
        for i in range(3):
            self.app.navigate_to('/pages/search/index')
            page = self.app.get_current_page()
            page.wait_for(2)

        pages_before = page.evaluate('getCurrentPages().length')
        self.assertGreater(pages_before, 1, '此时应多层页面')

        # switchTab
        self.app.switch_tab('/pages/home/index')
        page = self.app.get_current_page()
        page.wait_for(2)

        pages_after = page.evaluate('getCurrentPages().length')
        self.assertEqual(pages_after, 1, 'switchTab 后栈深应为 1')

    def test_navigate_back_with_params(self):

        self.app.navigate_to('/pages/search/index')
        page = self.app.get_current_page()
        page.wait_for(3)

        page.wait_for(2)

        # 验证返回到了上一页
        current_path = page.path
        self.assertNotIn('search', current_path)

## 二、移动端测试方法 + Charles 抓包

### 2.1 小程序真机测试流程

```
第一步：开启调试模式
  微信 → 发现 → 小程序 → 右上角「...」→ 开发调试 → 开启调试
  （开启后右下角会出现绿色 vConsole 按钮）

第二步：真机调试
  开发者工具 → 真机调试 → 扫码 → 手机进入调试模式
  → 手机上操作，开发者工具实时显示日志

第三步：收集信息
  - 点击 vConsole → 查看 console.log / 网络请求 / Storage / 系统信息
  - 性能面板：右上角「...」→ 打开调试 → Performance
```

### 2.2 Charles 抓包（小程序 API 请求）

小程序的 `wx.request` 走的是系统 HTTP 协议而不是浏览器 DevTools，没法直接用浏览器开发者工具抓包。用 Charles 代理来抓。

**配置步骤：**

```
1. PC 端 Charles 配置
   Proxy → Proxy Settings → HTTP Proxy 勾上，Port: 8888
   Proxy → SSL Proxying Settings → 勾上 Enable SSL Proxying
   → Add: Host: *.digiplus-intl.com, Port: 443

2. 手机端配置
   WiFi → 代理 → 手动
   → 服务器: PC 的 IP（如 192.168.1.100）
   → 端口: 8888

3. 安装 Charles 证书
   手机浏览器访问 chls.pro/ssl → 下载证书 → 安装
   iOS: 设置 → 通用 → 关于本机 → 证书信任设置 → 信任证书
   Android: 设置 → 安全 → 加密与凭据 → 安装证书

4. 开始抓包
   手机操作小程序 → Charles 里看到 HTTPS 请求的完整内容
```

**抓包能帮你做什么：**

| 场景 | 怎么看 |
|------|--------|
| 请求参数不对 | 看 Request → Contents → JSON | 
| 接口返回 500 | 看 Response → Contents → error message |
| 请求没发出去 | 看 Sequence 里有没有这条请求 |
| 请求超时 | 看 Duration 时间 |
| 重复请求 | 看 Sequence 里同 URL 出现了几次 |
| token 过期 | 看 Response → code === 401 时请求头里 token 是否正确 |

### 2.3 iOS / Android 差异排查速查表

| 常见坑 | iOS 表现 | Android 表现 | 排查方法 |
|--------|---------|-------------|---------|
| Date 解析 | `new Date('2024-01-01')` Invalid | 正常 | 统一 `replace(/-/g, '/')` |
| input placeholder | 偏上 | 居中 | 加 `line-height` |
| scroll-view 惯性 | 默认平滑 | 部分机型卡顿 | 加 `enhanced` + `show-scrollbar` |
| 蓝牙 API | 正常 | 部分厂商阉割 | 测主流机型 |
| 图片 mode="aspectFill" | 正常 | 部分裁剪位置异常 | 测不同比例图片 |
| 底部 safe-area | 有 home indicator | 无 | `env(safe-area-inset-bottom)` |
| 文件选择 | 限制严格 | 相对宽松 | 测文件大小上限 |
| 定位权限 | 首次弹系统弹窗 | 直接返回结果 | 测 fail 回调 |
| 微信字体大小 | 影响页面 | 需单独适配 | `wx.getSystemInfoSync().fontSizeSetting` |

### 3.1 框架 + 登录 + 业务流程

```python
# test_api_auth.py
import requests
import pytest


class TestAuth:
    """登录鉴权接口测试"""

    BASE_URL = 'https://star.digiplus-intl.com/api'

    @pytest.fixture(scope='class')
    def token(self):
        """登录获取 token，整个类复用"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={
                'email': 'liying@ama-auto.com',
                'password': '3149390154Li'
            },
            timeout=10
        )
        assert resp.status_code == 200, f'登录失败: {resp.text}'
        data = resp.json()
        assert data['code'] == 0, f'业务失败: {data.get("msg")}'
        return data['data']['token']

    def test_login_success(self):
        """正常登录"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={
                'email': 'liying@ama-auto.com',
                'password': '3149390154Li'
            },
            timeout=10
        )
        assert resp.status_code == 200
        body = resp.json()
        assert body['code'] == 0
        assert 'token' in body['data']

    def test_login_wrong_password(self):
        """密码错误"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={
                'email': 'liying@ama-auto.com',
                'password': 'wrong123456'
            },
            timeout=10
        )
        body = resp.json()
        assert body['code'] != 0, '密码错误应返回非 0'

    def test_login_empty_body(self):
        """请求体为空"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={},
            timeout=10
        )
        body = resp.json()
        assert body['code'] != 0, '空请求体应返回错误'

    def test_login_missing_email(self):
        """缺少 email 字段"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={'password': '123456'},
            timeout=10
        )
        body = resp.json()
        assert body['code'] != 0

    def test_login_sql_injection(self):
        """SQL 注入攻击"""
        resp = requests.post(
            f'{self.BASE_URL}/auth/login',
            json={
                'email': "' OR '1'='1",
                'password': "' OR '1'='1"
            },
            timeout=10
        )
        body = resp.json()
        assert body['code'] != 0, 'SQL 注入不能登录成功'

    def test_token_valid(self, token):
        """token 有效——用登录后的 token 调一个需要鉴权的接口"""
        resp = requests.get(
            f'{self.BASE_URL}/user/info',
            headers={'Authorization': f'Bearer {token}'},
            timeout=10
        )
        assert resp.status_code == 200, f'token 无效: {resp.text}'
        body = resp.json()
        assert body['code'] == 0

    def test_token_expired(self):
        """过期 token"""
        resp = requests.get(
            f'{self.BASE_URL}/user/info',
            headers={'Authorization': 'Bearer expired_token_12345'},
            timeout=10
        )
        body = resp.json()
        assert body['code'] == 401, f'过期 token 应返回 401，实际: {body.get("code")}'


if __name__ == '__main__':
    pytest.main(['test_api_auth.py', '-v'])
```

### 3.2 数据驱动 + 批量测试

```python
# test_api_data_driven.py
import pytest
import requests

BASE_URL = 'https://star.digiplus-intl.com/api'

# 数据驱动：一条用例对应多组数据
@pytest.mark.parametrize('email,password,expected', [
    # (邮箱,              密码,          预期 code)
    ('liying@ama-auto.com', '3149390154Li', 0),      # 正常
    ('',                    '123456',       1),       # 空邮箱
    ('test@test.com',       '',             1),       # 空密码
    ('not-email-format',    '123456',       1),       # 非邮箱格式
    ('a' * 500,             '123456',       1),       # 超长邮箱
])
def test_login_matrix(email, password, expected):
    """批量参数化测试登录"""
    resp = requests.post(
        f'{BASE_URL}/auth/login',
        json={'email': email, 'password': password},
        timeout=10
    )
    body = resp.json()
    assert body['code'] == expected, \
        f'{email} → 预期 code={expected}，实际 code={body["code"]}, msg={body.get("msg")}'


# 并发测试（用 threading 简单模拟）
import threading
import time

def test_concurrent_login():
    """10 个用户同时登录"""
    results = []
    lock = threading.Lock()

    def login(idx):
        resp = requests.post(
            f'{BASE_URL}/auth/login',
            json={'email': 'liying@ama-auto.com', 'password': '3149390154Li'},
            timeout=15
        )
        with lock:
            results.append({
                'idx': idx,
                'code': resp.status_code,
                'time': resp.elapsed.total_seconds()
            })

    threads = [threading.Thread(target=login, args=(i,)) for i in range(10)]
    for t in threads:
        t.start()
    for t in threads:
        t.join()

    # 断言
    assert len(results) == 10, f'应全部完成，实际 {len(results)}'
    for r in results:
        assert r['code'] == 200, f'线程#{r["idx"]} 返回 {r["code"]}'
    avg_time = sum(r['time'] for r in results) / len(results)
    print(f'10 并发平均响应: {avg_time:.2f}s')
```

## 四、模拟面试问答

### 第1题：说一下你对小程序测试和 App 测试区别的理解？

> 最大的区别是运行环境和版本依赖的复杂度。
>
> App 测试主要关注系统版本（iOS 14/15/16、Android 12/13/14）和机型的适配。
>
> 小程序多了一层：微信版本 × 基础库版本 × 系统版本的三维矩阵。同一个小程序在不同微信版本上行为可能不一样，因为基础库随微信版本分发。
>
> 另外小程序的调试方式也不一样——App 可以用 Xcode/Android Studio，小程序依赖微信开发者工具和 vConsole。性能上限也不同，小程序受基础库和 WebView 限制，比原生 App 更容易遇到性能瓶颈。

---

### 第2题：给你一个新功能需求，你怎么设计测试方案？

> 我分五步走：
>
> **第一步：需求分析**。确认功能目标、涉及哪些微信 API、依赖的最低基础库版本、是否需要分包加载。
>
> **第二步：测试场景矩阵**。正常流程 + 异常（网络中断、授权拒绝、接口超时）+ 边界（输入长度、金额极值）+ 微信特有场景（切后台回来、分享进入、扫码进入、下拉刷新）。
>
> **第三步：兼容性设计**。微信版本 × 基础库版本 × 系统 × 机型的覆盖策略。核心路径真机测，边缘场景用云测平台补充。
>
> **第四步：自动化策略**。核心回归用例进 minium 自动化套件。接口层用 Python 做独立验证。
>
> **第五步：发布验证**。审核前 checklist 预检（隐私协议、类目匹配、无空白页），灰度后盯反馈。

### 第3题：你怎么维护小程序自动化用例？

> 我用 minium + Pytest 管理自动化用例，维护上注意几点：
>
> 1. **分层**：登录、清理数据等公共操作放 conftest.py，每个页面一个 test 文件
> 2. **稳定性**：脆弱的选择器用 data-* 自定义属性替代 CSS class，避免改版导致用例大面积失效
> 3. **失败截图**：用例失败自动截图，方便定位是环境问题还是真 bug
> 4. **和发版节奏对齐**：每个版本新增的功能必须同步补充自动化用例
> 5. **定期跑**：代码合入触发接口层 + 组件层，每日定时跑 UI 层全量

### 第4题：微信客户端发版后收到用户反馈小程序闪退，你怎么排查？

> 第一步快速收集信息：问用户微信版本、手机型号、系统版本、操作路径。
>
> 第二步去小程序后台「运维中心」查看错误日志，看有没有 JS 报错堆栈、接口异常。
>
> 第三步看是不是基础库版本相关——用户是不是升级了微信导致基础库版本变化？某个 API 在新版本基础库上的行为是否变了？
>
> 第四步用相同条件复现。如果复现不了，考虑是不是和用户数据有关、是不是并发场景。
>
> 第五步定位到根因后推动开发修，验证通过后补充回归用例，同时在用户反馈系统里闭环。

### 第5题：setData 调用有什么要注意的？你测基础库的时候怎么测 setData？

> setData 是逻辑层向渲染层传数据的唯一通道，有几个限制：
> - 单次数据量建议 < 256KB
> - 调用频率建议 < 20 次/秒
> - 只传变化的数据，不要整个对象丢过去
>
> 我测基础库 setData 的时候会写一个 demo：
> - 用不同大小的数据（64KB、128KB、256KB、512KB、1MB）测单次上限
> - 用 16ms 间隔连续调 60 次测高频场景，看基础库有没有 warn
> - 在不同基础库版本上跑同样的用例，对比回调耗时，看有没有性能退化
> - 跨页面跳转时 setData 然后立刻 navigateTo，看数据有没有丢

### 第7题：小程序性能测试你关注哪些指标？怎么测？

> 四个核心指标：
>
> **首屏加载时间**：开发者工具 Network 面板看首页接口耗时 + 渲染时间。要求首屏 < 2s。
>
> **setData 耗时**：在 demo 里用 `setData` 的回调计时，对比不同基础库版本的耗时。
>
> **内存占用**：微信开发者工具 Memory 面板，长时间 monkey test 后看内存曲线有没有持续上涨。
>
> **页面切换帧率**：反复进入/返回页面，用 Performance 面板看帧率有没有掉帧。
>
> 另外微信开发者工具有「体验评分」功能（Audits），可以一键扫描包体积、请求数量、setData 调用等，作为性能测试的基准线。

### 第8题：你用过哪些抓包工具？怎么分析一个接口请求异常？

> 主要用 Charles 和微信开发者工具自带的 Network 面板。
>
> Charles 抓真机上的请求，用来排查小程序在真实环境下的接口问题。
>
> 分析接口异常的顺序：
> - 先看请求有没有发出去——Network 里没有这条请求，说明前端逻辑有问题
> - 发了但没响应——看是不是超时、域名白名单、SSL 证书问题
> - 有响应但 status 不对——500 看后端日志，401 看 token 是不是过期，403 看权限
> - status 200 但业务 code != 0——看请求参数是不是拼错了、业务逻辑是不是不符合预期
>
> 定位到之后截图保存，附加到缺陷报告里，方便开发快速定位。

### 第9题：你开发维护小程序测试 demo，怎么保证 demo 本身的质量？

> 第一，demo 代码和业务代码一样要走版本管理，写完先自测。
>
> 第二，demo 的每个测试场景都要有明确的预期结果，写在页面里或注释里，让人一看就知道怎么判定 PASS/FAIL。
>
> 第三，demo 页面结构要利于自动化——数据暴露在 `getApp().globalData` 里，按钮加 `data-*` 属性标识测试用例，方便 minium 直接采集结果。
>
> 第四，每次基础库升级跑一遍 demo 的自动化套件，发现 demo 本身的兼容性问题及时修。
