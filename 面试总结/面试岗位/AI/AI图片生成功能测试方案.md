# AI 图片生成功能测试方案

---

## 一、功能拆解

把需求拆成 3 个核心能力：

```
能力1：多图选择       → 用户选 2+ 张模块图片作为输入
能力2：AI 融合生成    → 点击生成，AI 将多张图融合成一张新图
能力3：局部重生成     → 在新图上框选某块区域，AI 重新生成该区域
```

对应的用户操作路径：

```
选图页 → 选 2~N 张模块图 → 点击「生成」
  → 等待 AI 生成 → 查看生成结果
  → 不满意？框选某区域 → 点击「局部重生成」
  → 查看新结果 → 满意则保存 / 不满意继续局部重生成
```

## 三、AI 特有测试（核心难度）

### 3.1 输出质量评估

| 维度 | 怎么测 | 判定标准 |
|------|--------|---------|
| **融合自然度** | 选多组不同风格的图生成，人工打分 1-5 | 无明显拼接痕迹、光照色彩协调 |
| **局部重生成一致性** | 框选区域重生成后，和周围区域的过渡 | 无明显的边界线、色差跳变 |
| **内容合理性** | 输入猫图+沙发图 → 生成 | 猫应该在沙发上或旁边，不应出现违背物理规律的画面 |
| **风格遵循度** | 输入 2 张二次元风格 → 生成 | 输出也应是二次元风格，不应变成写实 |

**测试方法**：

准备 10 组标注好的「输入 → 期望特征」测试集。每组需要 3 个以上测试人员独立打分。

```
示例测试集：
组1: 写实卧室 + 写实沙发 → 期望：写实风格融合，无明显拼接
组2: 二次元人物 + 二次元背景 → 期望：二次元风格保持一致
组3: 照片级人像 + 卡通背景 → 期望：允许风格不统一，但不应出现畸形
组4: 纯色背景图 + 复杂前景图 → 期望：前景正确融入背景，无白边
组5: 低分辨率图(240p) + 高清图(4K) → 期望：输出不低于低分辨率图的质量
```

### 3.2 局部重生成精准度测试

```
测试方法：构图法

1. 准备一张 4 宫格输入图（左上红、右上蓝、左下绿、右下黄）
2. 选其他 2 张图生成一张融合图
3. 在结果图上框选左上 1/4 区域 → 重生成
4. 检查：只有左上角变化，其余 3/4 保持不变

量化标准：
- 非选区像素变化率 < 5%（通过像素对比工具验证）
- 选区和非选区的边界过渡自然
```

### 3.3 同一输入多次生成的差异性

| 编号 | 场景 | 预期 |
|------|------|------|
| AI-DIFF-01 | 同一组图连续生成 5 次 | 每次结果不完全相同，但风格和质量一致 |
| AI-DIFF-02 | 同一组图 + 同一选区连续局部重生成 5 次 | 框选区域每次有变化，非框选区域不变 |

**怎么测**：取 5 次结果的像素 hash，两两对比，相似度应在 80%~99% 之间（不完全相同，但也不应差异过大）。

## 六、性能测试

| 指标 | 目标 | 怎么测 |
|------|------|--------|
| 生成耗时 | 2 张图 < 15s，9 张图 < 60s | 多次测试取 P95 |
| 局部重生成耗时 | < 生成的 60%（因为只改一部分） | 同一张图测 10 次取 P95 |
| 图片上传耗时 | < 3s/张（4G 网络） | 弱网和正常网络分别测 |
| 内存占用 | 生成过程中内存增量 < 200MB | 微信 Performance 面板 |
| 页面帧率 | 选图/框选操作不掉帧 | 开发者工具 FPS 面板 |
| 并发生成 | 100 人同时点生成 | JMeter/Locust 压测后端接口 |
| 冷启动 | 首次进入功能 < 3s | 清除缓存后测量 |

## 十、面试时怎么说

> 这个功能我分三层来测：
>
> **第一层——基础功能**：多图选择（2 张到上限、取消、未选就点生成）、AI 生成（loading、超时、失败重试、网络异常）、局部重生成（框选交互、选区边界、多次重生成叠加）、结果操作（保存、分享、重新生成）。
>
> **第二层——AI 特有的质量评估**：我会准备一个标注好的测试集（含不同风格、不同分辨率的图），生成后评估融合自然度、局部重生成的一致性、风格遵循度。局部重生成我会用构图法测——准备一张多区块的图，重生成左上角，验证其他三角的像素没变。
>
> **第三层——性能 + 兼容性**：P95 生成耗时、并发压测、iOS/Android 不同机型的兼容性、内存占用、弱网下的超时策略。
