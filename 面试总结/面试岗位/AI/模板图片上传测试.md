# 模板图片上传——测试用例

---

## 功能流程

```
选择图片 → 裁剪/确认 → 上传中 → 上传成功(缩略图展示) / 上传失败(重试)
                                                ↓
                                    进入模板库，可被选择使用
```

---

## 一、图片选择

| 编号 | 场景 | 操作 | 预期 |
|------|------|------|------|
| UP-01 | 从相册选 1 张 | 点击上传 → 从相册选图 | 进入裁剪页或直接上传 |
| UP-02 | 拍照上传 | 点击上传 → 拍照 | 调起相机，拍照后进入确认页 |
| UP-03 | 从微信聊天记录选图 | 点击上传 → 从聊天记录选 | 正常选择 |
| UP-04 | 一次选多张 | 相册中勾选 5 张 → 确认 | 支持批量上传 |
| UP-05 | 选图后取消 | 相册弹出 → 点取消 | 回到上传入口，无任何变化 |
| UP-06 | 相册权限-已授权 | 已有权限 → 选图 | 直接打开相册 |
| UP-07 | 相册权限-未授权 | 首次使用 → 选图 | 弹系统授权弹窗 |
| UP-08 | 相册权限-被拒绝 | 拒绝授权 → 再次点上传 | 提示「请在设置中开启相册权限」，引导跳设置 |
| UP-09 | 相册权限-仅部分照片 | iOS 选择「选中的照片」 | 只能看到被授权的照片 |
| UP-10 | 相册为空 | 手机没有图片 → 选图 | 提示相册为空，引导拍照 |
| UP-11 | 选择最近删除的图片 | 相册里选一张刚删的图 | 无法选择或提示图片不可用 |

## 二、图片校验

### 2.1 格式校验

| 编号 | 场景 | 预期 |
|------|------|------|
| FMT-01 | JPEG（.jpg/.jpeg） | ✅ 支持 |
| FMT-02 | PNG（含透明通道） | ✅ 支持 |
| FMT-03 | WebP | ✅ 支持（微信生态常用） |
| FMT-04 | GIF 动图 | 取第一帧，或提示「不支持 GIF」 |
| FMT-05 | BMP/TIFF | 提示「不支持的图片格式」 |
| FMT-06 | HEIC（iPhone 实况照片） | 自动转 JPEG，或提示不支持 |
| FMT-07 | 改后缀的假图片（.txt 改名 .png） | 校验文件头，提示「图片已损坏」 |
| FMT-08 | 无后缀文件 | 提示「请选择图片文件」 |

### 2.2 尺寸/分辨率校验

| 编号 | 场景 | 预期 |
|------|------|------|
| SZ-01 | 正常尺寸（1024×1024） | ✅ 通过 |
| SZ-02 | 最小尺寸边界（假设 ≥ 512×512） | 刚好 512×512 → 通过；511×512 → 提示「分辨率过低」 |
| SZ-03 | 最大尺寸边界（假设 ≤ 4096×4096） | 刚好 4096 → 通过；4097 → 提示「图片尺寸过大」 |
| SZ-04 | 极端宽度（1×1024） | 提示「图片比例不符合要求」 |
| SZ-05 | 极端高度（1024×1） | 同上 |
| SZ-06 | 超小图（10×10） | 提示「分辨率过低」 |
| SZ-07 | 超大图（8000×8000） | 上传超时或提示尺寸过大 |

### 2.3 文件大小校验

| 编号 | 场景 | 预期 |
|------|------|------|
| SIZE-01 | 正常大小（500KB） | ✅ 通过 |
| SIZE-02 | 边界值（刚好 20MB） | ✅ 通过或提示上限 |
| SIZE-03 | 超大文件（50MB） | 提示「文件大小不能超过 20MB」 |
| SIZE-04 | 接近上限（19.9MB） | ✅ 通过，上传较慢 |
| SIZE-05 | 零字节图片 | 提示「图片无效」 |

### 2.4 内容校验

| 编号 | 场景 | 预期 |
|------|------|------|
| CT-01 | 正常图片 | ✅ 通过 |
| CT-02 | 纯白/纯黑图 | ⚠️ 取决于业务：可能提示「请上传有效内容」或放行 |
| CT-03 | 模糊到看不清的图 | ⚠️ 取决于业务：可能提示质量过低 |
| CT-04 | 涉黄/涉政/暴力图片 | 后端审核拦截，提示「图片包含违规内容」或上传成功但审核不通过 |
| CT-05 | 带水印/二维码的图 | ⚠️ 取决于业务 |
| CT-06 | 包含文字的图 | ✅ 通过（但需告知用户字可能被 AI 扭曲） |

## 三、上传过程

| 编号 | 场景 | 操作 | 预期 |
|------|------|------|------|
| PR-01 | 正常上传 | 选图 → 确认 → 等待 | 进度条 0%→100%，上传完成显示缩略图 |
| PR-02 | 上传进度展示 | 上传大图（10MB+）| 进度条/百分比实时更新 |
| PR-03 | 上传中取消 | 上传中 → 点取消 | 上传中断，不留脏数据 |
| PR-04 | Wi-Fi 上传 | 正常网络 | 成功 |
| PR-05 | 4G/5G 上传 | 移动网络 | 成功，如有流量提醒则弹提示 |
| PR-06 | 弱网上传（2G/限速 50KB/s） | 弱网下上传大图 | 超时提示，可重试 |
| PR-07 | 上传中断网 | 上传到 50% → 切飞行模式 | 提示网络异常，可重试 |
| PR-08 | 网络恢复后重试 | 上传失败 → 恢复网络 → 点重试 | 从 0 开始或断点续传，最终成功 |
| PR-09 | 上传中切后台 | 上传中 → 切微信到后台 | 后台继续上传，回来后显示进度或结果 |
| PR-10 | 上传中锁屏 | 上传中 → 锁屏 | 后台继续上传 |
| PR-11 | 上传中杀微信 | 上传中 → 杀进程 | 重开微信，未传完的图需要重传 |
| PR-12 | 上传中来电话 | 上传中 → 接电话 | 通话结束回来看状态 |
| PR-13 | 批量上传 | 一次选 9 张 → 上传 | 逐张上传或并发，每张有独立进度 |
| PR-14 | 批量上传中某一张失败 | 9 张中第 3 张上传失败 | 成功的保留，失败的有重试入口 |

## 四、上传成功后

| 编号 | 场景 | 预期 |
|------|------|------|
| RS-01 | 缩略图展示 | 上传后在模板列表显示缩略图 |
| RS-02 | 点击缩略图预览 | 全屏预览，可左右滑动浏览 |
| RS-03 | 上传多张后顺序 | 按上传时间倒序或自定义排序 |
| RS-04 | 删除模板图片 | 长按或编辑模式 → 删除 → 二次确认 |
| RS-05 | 删除后模板列表更新 | 删除的图不显示，其他图不受影响 |
| RS-06 | 模板名称 | 上传后自动生成或手动命名 |
| RS-07 | 模板图片数量上限 | 达到上限后提示「模板数量已满，请删除后再上传」 |
| RS-08 | 新上传的图立即可用 | 上传完成 → 去选图页 → 新图出现在备选列表里 |

## 七、异常

| 编号 | 场景 | 预期 |
|------|------|------|
| EX-01 | 手机存储空间满 | 上传时本地缓存失败 → 提示空间不足 |
| EX-02 | 服务端存储满 | 后端返回存储满 → 友好提示，不崩溃 |
| EX-03 | 图片被安全策略拦截 | 返回拦截信息 → 提示「图片不符合规范」 |
| EX-04 | 上传接口变更/不兼容 | 返回非预期结构 → 兜底处理，不白屏 |
| EX-05 | Cookie/Token 过期 | 上传中 token 过期 → 返回 401 → 刷新 token 重传 或 跳登录 |
| EX-06 | 重复上传同一张图 | 连续两次选同一张 → 去重 或 允许重复 |

## 九、面试回答模板

> "上传模板图片我分六个方面测：
>
> 第一，**选图入口**——相册、拍照、聊天记录，三个入口有没有都通。相册权限被拒绝时有没有引导去设置。
>
> 第二，**文件校验**——格式（JPEG/PNG/WebP 放行，GIF/HEIC 要么处理要么提示）、尺寸（上下限边界，刚好超限的情况）、大小（上限边界）、内容（纯黑纯白、模糊图、违规内容有没有拦截）。
>
> 第三，**上传过程**——正常上传有进度条、上传中可以取消、弱网下超时有重试、切后台/锁屏/来电话的容错。
>
> 第四，**上传后**——缩略图正常显示、可预览、可删除、达到数量上限有提示。
>
> 第五，**批量上传**——一次传多张时每张独立进度、某一张失败不影响其他、取消后不留脏数据。
>
> 第六，**性能**——单张 2MB 图 < 3s、批量 9 张 < 30s，上传过程内存不暴涨。"
