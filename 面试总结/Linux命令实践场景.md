# Linux 常用命令在软件测试中的实践场景

## 文件/目录操作

| 命令 | 测试实践场景 |
|------|-------------|
| `pwd` | 查看当前所在目录，确认日志文件、应用部署包路径是否正确 |
| `ls -al` | 查看部署目录下是否有新上传的jar/war包，查看日志文件是否生成 |
| `cd 目录` | 切换到日志目录、应用部署目录查看文件 |
| `mkdir -p /data/test/logs` | 递归创建多级目录，父目录不存在会自动创建；如果不加 `-p`，父目录不存在会直接报错，需要一层层手动创建 |
| `rm -rf *.log` | 清理测试环境中过期的日志文件，腾出磁盘空间 |
| `cp app.jar /opt/application/` | 将本地构建好的应用包复制到测试环境部署目录 |
| `mv app.jar app.bak` | 部署新版本前，将旧版本备份，出问题可以快速回滚 |
| `cat app.log | grep ERROR` | 查看整个日志文件，过滤出ERROR级别的错误 |
| `tail -f app.log` | **最常用**：实时查看应用启动日志、接口请求日志，调试问题 |
| `tail -100 app.log` | 查看日志最后100行，快速定位最近发生的错误 |
| `head -100 app.log` | 查看日志开头部分，排查应用启动时的错误 |

## 进程相关

| 命令 | 测试实践场景 |
|------|-------------|
| `ps -ef \| grep java` | 查找Java应用进程是否启动成功，获取进程ID |
| `kill -9 12345` | 应用启动卡住或端口占用，强制杀死进程后重启 |
| `top` | 测试环境应用响应慢，查看哪个进程CPU/内存占用过高，定位性能问题 |
| `htop` | 交互式查看进程资源占用，比top更直观 |

## 查找与搜索

| 命令 | 测试实践场景 |
|------|-------------|
| `find /var/log -name "*.log"` | 在指定目录下查找所有.log后缀的日志文件 |
| `find . -name "*error*"` | 按文件名模糊查找，找包含error关键词的日志文件 |
| `grep -rn "NullPointerException" /var/log` | 在整个目录下递归搜索哪个日志文件中出现了空指针异常，定位错误位置 |
| `grep -n "用户登录异常" app.log` | 搜索关键词并显示行号，快速跳转到错误所在行 |
| `wc -l app.log` | 统计日志文件行数，估算数据量 |

## 网络相关

| 命令 | 测试实践场景 |
|------|-------------|
| `curl http://localhost:8080/health` | 测试环境部署完成后，调用健康检查接口验证应用是否启动成功 |
| `curl -X POST -d "param=value" http://localhost/api/test` | 简单测试接口请求，验证接口连通性 |
| `netstat -anp \| grep 8080` | 启动应用时报端口占用，查看哪个进程占用了8080端口 |
| `lsof -i:8080` | 另一种查看端口占用的方式 |
| `ping 192.168.1.100` | 测试环境网络不通，ping一下看网络是否连通 |
| `telnet db-host 3306` | 检查测试环境应用服务器能否连通MySQL数据库端口 |

## 测试工作中常见问题排查场景

### 场景一：应用启动失败，怎么排查？

```bash
# 1. 查看进程是否启动
ps -ef | grep app-name

# 2. 如果没启动，查看启动日志
cd /var/log/app
tail -100 app.log

# 3. 搜索关键字Error/Exception定位错误
grep -n "Exception" app.log

# 4. 如果是端口占用，找到占用进程
netstat -anp | grep 8080
kill -9 <pid>

# 5. 如果是磁盘满了清理空间
df -h
```

### 场景二：接口请求返回500，怎么在Linux排查？

```bash
# 1. 先看最新日志
cd /var/log/app
tail -f app.log

# 2. 再请求一次接口，看实时输出的错误堆栈

# 3. 如果日志太多，搜索关键字
grep -n "500\|ERROR" app.log
```

### 场景三：测试环境内存溢出OOM，怎么排查？

```bash
# 1. 查看内存使用情况
free -h

# 2. 看哪个进程占用内存最高
top

# 3. 查看应用日志中的OOM异常
grep -n "OutOfMemory" app.log
```

## 面试问答总结

**Q：测试工作中你常用哪些Linux命令？**

>A：我在测试环境主要用这些命令：
>- 查看日志：`tail -f`、`grep` 搜索错误，这两个是最常用的，排查问题基本都靠它们
>- 进程操作：`ps -ef` 找进程，`kill -9` 杀进程
>- 网络排查：`netstat -anp | grep 端口` 看端口占用，`curl` 测试接口连通性
>- 资源查看：`df -h` 看磁盘，`free -h` 看内存

**Q：你怎么查找日志中包含error的行？**

>A：用 `grep "ERROR" 日志文件名`，如果想显示行号就加 `-n` 参数，`grep -n "ERROR" app.log`。如果要在整个目录递归找就是 `grep -rn "ERROR" 目录`。

**Q：应用OOM你怎么排查？**

>A：我会先按这个步骤：
>1. `free -h` 看系统剩余内存够不够
>2. `top` 看哪个进程占用CPU/内存最高
>3. `grep "OutOfMemory" 日志文件` 看应用日志有没有OOM异常堆栈
>4. 如果是Java应用，还可以用jstack、jmap去导出线程和堆信息进一步分析

## 核心要点

软件测试对Linux的要求：
- **不需要懂内核编程、shell深度开发**
- 重点掌握：**会看日志、会找错误、会启停应用、会排查常见问题**
- 面试考察重点是：你**实际用过**这些命令解决问题，而不是背参数
