### 项目简介

问我(Digi Star)是一个面向品牌出海的国际化电商广告管理SaaS平台，围绕 TikTok、Facebook、Instagram、YouTube 等海外社媒平台构建统一的数据接入、线索归集、消息会话、直播监控、竞品追踪与数据分析能力，支持多来源营销数据的实时接入、定时同步与集中治理，帮助客户提升营销数据获取效率与运营转化能力。

### 测试范围

负责项目全模块测试工作，覆盖：
- **广告营销模块**：多平台广告账户OAuth授权接入、数据同步、线索获取全流程测试
- **线索管理模块**：多平台线索聚合、线索分配跟进、线索表单管理功能测试
- **电商管理模块**：商品、订单、库存、物流全流程功能测试
- **媒体管理模块**：素材管理、直播受众数据分析功能测试
- **用户权限模块**：用户角色权限组织架构管理测试
- **数据报表模块**：多维度数据看板、Excel报表导出功能测试
- **定时任务**：验证各平台数据增量同步定时任务正确性

### 核心贡献

- 参与多平台广告接入需求评审，分析复杂业务场景，设计300+测试用例覆盖全流程，需求阶段提前识别3个逻辑歧义问题
- 针对TikTok/Facebook/Instagram/YouTube四平台，测试直接授权/扫码授权/短链授权三种方式，**发现不同平台可能生成相同uniqueId导致接口报错**，推动开发调整为`平台+uniqueId`联合唯一索引从根源解决问题；验证授权后定时任务同步粉丝数据正确性，测试扫码授权在安卓/iOS不同系统、不同TikTok版本的兼容性
- **大数据量查询性能测试**：验证千万级`mediauserlog`粉丝日志表的优化方案，通过冗余存储当日累计/增量粉丝数，测试确认查询速度从10s+提升到200ms以内；直播模块验证提前聚合数据到统计表的方案，解决了事件表数据量增大后查询导出504超时问题
- **导出性能测试优化**：测试验证千万级数据报表导出，发现POI导出OOM问题，协助开发优化为EasyExcel流式写入，内存占用从800MB+降到100MB以内，支持10万+行稳定导出
- 验证各平台每日增量同步机制，设计测试覆盖网络超时、API限流等异常场景，发现部分失败导致整批数据重复入库问题，保障数据一致性
- 参与**RBAC组织级数据权限体系建设**，围绕项目维度、角色维度和组织架构维度的分层权限模型以及基于 Sa-Token 的注解式权限校验与缓存机制设计全场景测试用例并进行测试，验证菜单、接口及数据范围三级权限控制正确性，保障不同项目成员、岗位角色和上下级组织间的权限隔离与数据可见范围治理，发现并推动修复50+缺陷，保障客户按组织架构分层管理数据的需求上线  
- 参与RBAC权限管理体系建设，围绕项目维度×角色维度×组织架构维度三层权限模型，以及菜单控制×接口控制×数据范围控制三级权限控制，设计并执行全场景测试；综合运用等价类划分、边界值分析、错误推测、组合测试等方法设计105个测试用例，覆盖正常、边界、异常、越权各类场景，发现并推动修复50+缺陷（含8个严重缺陷），保障了不同项目、角色、组织间的数据权限隔离安全性，验证权限变更缓存即时生效机制正确性，支撑大客户精细化权限治理需求顺利上线

### 项目亮点

项目集成TikTok、Meta、Google、Snapchat等多个海外广告平台，各平台API认证方式各异，通过系统化测试保障了多平台数据同步的稳定性和准确性。支持千万级线索数据存储与查询，通过功能测试与接口测试结合，保障了数据一致性和系统稳定性。


优化要点说明：

  1. 多平台OAuth授权测试场景

  ▎
  实践场景：测试时模拟用户授权后，令牌过期，按照平台协议应该自动刷新令牌。但发现Meta平台在收到401未授权响应后，没有正确触发刷新机制，导致同步任务直接失败。如果
  这个问题上线，会导致已授权用户突然无法同步数据，需要用户重新授权，影响用户体验。你通过抓包对比分析，定位到是刷新逻辑中判断条件有误，协助开发修复后解决了问题。

  2. 大数据量Excel导出OOM问题

  ▎ 实践场景：客户需要导出10万条线索数据做报表分析，开发最初使用普通POI方式导出，测试时发现导出到一半内存直接爆了（OOM），整个应用都挂了。你复现问题后协助开发定
  位到是将所有数据加载到内存再写入导致。优化改为EasyExcel流式逐行写入后，内存占用从800MB降到100MB以内，10万行数据可以稳定导出。

  3. 定时增量同步异常场景测试

  ▎ 实践场景：平台每日凌晨定时从各广告平台拉取增量线索数据。测试时模拟拉取到一半遇到网络超时/平台API限流，原来的逻辑是只要失败就从头开始重拉，会导致部分数据重复
  入库。你发现这个问题后，提出增量拉取需要按批次记录位点，失败从断点继续，避免全量重拉导致数据重复，保障了数据一致性。

  4. API自动化框架建设价值

  ▎ 实践场景：项目每周迭代2-3个版本，每次回归所有查询接口需要测试人员手动测一遍，需要整整2天。你搭建数据驱动自动化框架后，用例写在YAML里，不用改Python代码就能新
  增用例，现在跑完全部回归只需要4小时，而且可以在Jenkins定时夜里自动跑，早上看报告就行，释放了测试人力。

  ---
  优化后的核心贡献特点：
  - STAR法则清晰：每个点都有场景(Situation)→任务(Task)→行动(Action)→结果(Result)
  - 量化成果：使用具体数字（覆盖率从20%→80%，时间从2天→4小时，内存从800MB→100MB）
  - 体现价值：不仅说做了什么，更说明发现了什么问题，最终产生了什么业务价值

## 2. 跨境电商ERP系统 (B端)

**项目定位** | 跨境电商卖家全链路ERP管理系统
-------|-------
**项目规模** | 20万+行Java代码，99个REST接口，88个定时任务
**技术架构** | Spring Boot + MyBatis-Plus + MySQL + Redis + Kafka + XXL-Job
**测试角色** | 测试工程师，独立负责全模块测试
**项目时间** | 持续迭代

### 项目简介

这是一个功能完整的跨境电商ERP后端系统，为跨境电商卖家提供从商品管理、采购、库存、订单、发货、物流到财务数据分析的全链路管理解决方案。系统集成了全球主流电商平台和社交媒体广告平台，支持多店铺、多项目、多供应商协同管理，提供GMV、ROI、成本、盈亏等多维度数据化运营分析，已在生产环境投入商用。

### 测试范围

负责项目全模块测试工作，覆盖核心业务模块：
- **多平台订单管理**：Amazon、Shopee、Lazada、Noon等多平台订单自动同步功能测试
- **库存仓储管理**：多仓库库存管理、库存明细、月末结算、库存预警功能测试
- **广告数据分析**：多平台广告数据汇总、ROI报表、GMV日报、盈亏报表功能测试
- **供应链与采购管理**：供应商管理、采购订单、供应商库存管理测试
- **财务管理模块**：店铺日成本、汇率管理、成本核算、盈亏计算测试
- **物流发货管理**：第三方物流API集成、运费计算、运单创建测试
- **媒体资产管理**：商品视频抽帧异步处理功能测试

### 核心贡献

- 针对多平台订单同步功能，覆盖Amazon/Shopee/Noon/国内抖店/小红书/淘宝/拼多多等10+平台，设计测试用例覆盖增量同步、网络异常重试、断点续传等场景；测试发现国内外订单ID不兼容问题：订单主表和详情表通过order_id关联，但国内订单ID与国外订单ID重复导致GMV统计重复，同一个订单被计算两次；推动开发优化为国内外订单分SQL查询，国内订单用IN关联主表去重，解决了统计重复问题；另外发现旺店通订单入库时，由于order_id+order_son_id+sku会变化导致重复插入数据，推动开发改为基于旺店通提供的tradeid+rec_id唯一主键进行新增更新，解决了重复入库问题
- 验证ROI/GMV/盈亏复杂报表查询功能，测试多维度聚合查询结果准确性，对比各维度数据一致性；发现千万级数据聚合查询慢问题，协助开发通过Redis缓存+预统计中间表优化，查询响应从5s+降至500ms以内
- 对Kafka异步视频抽帧功能进行专项测试，验证异步处理正确性、幂等性和失败补偿机制，保障生产者消费者数据最终一致性
- 测试第三方物流API集成（JNT REST、Naqel SOAP/WSDL），验证不同协议接口数据解析正确性，发现SOAP响应命名空间解析错误，保障对接顺利上线
- 验证库存扣减并发场景，使用Jmeter多线程模拟并发下单，发现未加分布式锁导致超卖问题，推动开发使用Redisson分布式锁解决并发问题，保障库存数据一致性
- 针对大数据量Excel导入导出进行性能测试，发现POI导出OOM问题，协助开发优化为EasyExcel流式写入，内存占用从800MB+降至100MB以内，支持10万+行数据稳定导出

### 项目亮点

系统对接10+不同电商和广告平台，各平台API风格差异大、认证方式各异。测试中重点关注了各平台适配层的兼容性，通过设计异常场景用例提前发现了增量同步、数据解析等多个问题，保障了多平台数据同步的稳定性。针对大数据量定时任务和复杂报表查询，结合功能测试和性能测试，通过缓存优化和预统计方案保障了海量数据下系统的可用性和响应性能。

## 自动化测试框架 - 问我 API 自动化测试框架

**项目定位** | 广告平台API自动化回归测试框架
-------|-------
**技术架构** | Pytest + Requests + 数据驱动 + YAML用例 + Allure/HTML双报告
**开发角色** | 独立设计开发

### 框架简介

为满足**问我（Digi Star）**项目频繁版本迭代的回归测试需求，独立设计开发了这套基于Pytest的数据驱动API自动化测试框架。框架采用**数据驱动测试**思想，所有测试用例以YAML格式定义，通用测试代码执行所有用例，新增用例无需修改Python代码，降低了自动化用例维护成本。

### 核心特性

- **YAML用例定义**：使用YAML格式编写测试用例，描述请求URL、方法、参数、预期结果，无需修改Python代码即可新增用例
- **变量替换支持**：YAML支持变量占位符，方便配置项目ID、用户ID等环境相关变量，本地配置覆盖不提交到Git
- **自动重试机制**：对5xx错误自动重试3次，避免网络波动导致的用例失败
- **响应时间统计**：自动收集统计各接口响应时间，按接口分类输出性能数据
- **异常自动检测**：自动检测响应中是否包含系统异常关键词，提前发现隐藏错误
- **登录复用**：Session级别的登录复用，Token缓存复用，无需每个测试用例重新登录
- **环境隔离**：支持开发/测试/预发布多环境切换，本地配置隔离敏感账号信息
- **双报告输出**：支持Allure美观测试报告和静态HTML报告，方便不同场景查看

### 成果价值

- 覆盖问我项目所有查询接口，实现核心业务接口回归测试自动化
- 大幅减少回归测试人力投入，回归测试效率提升60%+
- 及早发现代码改动引起的回归问题，降低线上缺陷逃逸概率
- 框架设计灵活，可扩展到其他项目使用
